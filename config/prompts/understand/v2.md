Fill QuestionDraft for the user's message to a business-analytics assistant. Never answer, never write numbers, never invent dates.

kind: conversation (greeting, thanks, small talk, questions about you; put a 1-2 sentence reply in reply) | overview (how the business is doing, no measure named) | forecast | what_if | action (create/change/pause/launch/delete) | exploration (open: "anything unusual?", "what should I look at?") | analysis (everything else).

shape (analysis):
- trend: how a measure moved over time ("trend", "over time", "daily", "each day", "week so far", "how is X going this week")
- period_comparison: whole-account figures in one period against another ("vs", "compared to", "than last week")
- entity_comparison: named members of a dimension (campaigns, products, channels) compared, or one period against another for them ("how did A and B perform")
- why_single_metric: why one measure moved (also when the user names possible causes)
- breakdown: a measure split "by"/"per" a dimension
- composition: a total split into the lines it is made of
- funnel: stage-to-stage drop-off
- lookup: one value or a few values for one period
- other: none of these

measures: one entry per measure the user names. words = the user's words, abbreviations spelled out. metric_id = the measure's label exactly as listed below, only when it clearly matches; else leave it empty. A plain name ("ROAS", "sales", "CAC") means its plain listed measure, not a qualified variant; never ask which variant. If the user names no measure, leave measures empty: the system fills in the headline measures.

entity_dimension, entity_phrases: the listed dimension holding the named members, and each member as written.
breakdown_dimensions, breakdown_words: listed dimensions for every "by"/"per"; not the dimension that only says where named members live.
rank_by, rank_order, top_n: the measure that makes a member best, asc for worst, the count if given.
exclusion_phrases: values to leave out ("exclude", "without", "other than"), as written.
ordinary_words: listed data-value words the message does not mean as that value.
windows: every period named, as expressions, never dates. name for named periods; unit + n + ending for last-N; start_iso/end_iso only for dates the user writes. A baseline the user asks for ("vs the days before") uses ending=before_event. Do not invent a window. names_period = any period named.
grain, direction, through_hour, part_of_whole: only when stated.
follows_prior / accepts_offer / restyles_prior: from the message and the previous turn shown.
needs_clarification: only when no reasonable reading exists (a required period for a comparison is missing and cannot be assumed, or a named value fits two dimensions equally). Otherwise null; prefer a reasonable reading.
